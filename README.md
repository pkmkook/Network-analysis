# 香港十八区网络质量分析看板

一个面向**香港十八区网络质量分析**的可复用 Web 看板，支持上传新的 `CSV / XLSX` 数据后，自动完成字段识别、数据清洗、区域评分、问题分布统计和多维可视化展示。

在线地址：[https://network-analysis-six.vercel.app](https://network-analysis-six.vercel.app)  
GitHub 仓库：[https://github.com/pkmkook/Network-analysis](https://github.com/pkmkook/Network-analysis)

## 1. 这个项目解决什么问题

传统的网络质量分析经常有几个痛点：

- 原始数据通常是 `Excel` 或 `CSV`，字段名称不统一，难以直接分析
- 不同行政区、场景、时段之间难快速横向对比
- 每次换一份新数据，都要重新写脚本、重新出图、重新整理汇报材料
- 非技术同学难以直接从原始数据中得到“哪个区最好、哪个区最差、主要问题在哪”

这个项目的目标，是把一次性的脚本分析能力做成一个**可重复使用的数据分析看板**：

- 第一次打开就能直接看默认模拟数据
- 下次上传新的数据文件，系统仍然能继续分析
- 不依赖固定文件名，也尽量不依赖完全一致的列名
- 结果适合日常分析，也适合面试展示和汇报演示

## 2. 业务上它能做什么

这个看板主要围绕“香港十八区网络质量”做分析，当前支持以下能力：

### 2.1 全港总览

- 展示当前样本量、日期范围、平均下载速率、平均时延、投诉率、满意度、SLA 达标率
- 统计主要网络问题分布，如 `网速慢`、`信号弱`、`高延迟`
- 展示 `5G / 4G / 4G/5G切换` 的样本结构
- 自动生成“最佳区域”“最需优化区域”“高峰风险提醒”等洞察结论

### 2.2 区域分析

- 对香港十八区进行综合评分和排行
- 查看某一区的平均下载、时延、投诉率、满意度、重复反馈率
- 支持查看某个行政区在不同场景下的网络表现
- 支持按区域、场景、时段、网络制式、问题类型筛选

### 2.3 数据工作台

- 上传新的 `CSV / XLSX` 数据文件
- 自动识别字段名并尝试映射到标准分析字段
- 当新文件列名不完全一致时，支持手动字段映射
- 输出数据质量提示，如缺失关键字段、空值、日期异常
- 支持导出摘要 `JSON` 和标准化后的 `CSV`

## 3. 为什么这个看板是“可复用”的

这个项目不是只给一份固定样本画图，而是专门做了可复用的数据接入层。

核心思路是：

1. 先把外部文件解析成原始表格数据
2. 再将原始列名映射到系统内部统一的标准字段
3. 然后把每一行都转成统一结构的标准记录
4. 最后所有分析和可视化都只基于标准记录进行计算

也就是说，只要新数据的关键字段能识别或映射成功，系统就可以自动重新分析。

## 4. 技术实现思路

### 4.1 技术栈

- 前端框架：`React 18`
- 语言：`TypeScript`
- 构建工具：`Vite`
- 路由：`react-router-dom`
- 状态管理：`zustand`
- 图表：`Recharts`
- 文件解析：`Papa Parse` + `SheetJS/xlsx`
- 样式：`Tailwind CSS`
- 测试：`Vitest`
- 部署：`Vercel`

### 4.2 架构分层

项目大致可以分成四层：

#### 页面层

负责展示与交互：

- `总览页`
- `区域分析页`
- `数据工作台`

#### 状态层

负责保存当前数据集、筛选条件、字段映射、当前选中区域等共享状态。

#### 数据标准化层

负责处理外部上传数据：

- 自动识别表头
- 别名映射
- 数值/日期格式统一
- 缺失值处理
- 统一转成 `StandardRecord`

#### 分析引擎层

负责聚合计算：

- 样本量和日期范围
- 平均下载速率 / 上传速率 / 时延 / 抖动
- 投诉率 / 满意度 / SLA 达标率
- 区域综合评分
- 问题热图
- 自动业务洞察

## 5. 关键设计亮点

### 5.1 字段映射机制

真实数据里，列名未必总是固定的，比如：

- `香港行政区`
- `地区`
- `区域`
- `district`

这些其实都可能表示同一个字段。

所以项目里内置了一套**标准字段 + 别名字典**机制，会优先自动匹配；如果匹配失败，用户也可以手动绑定字段。

这一步决定了项目是否真的“可复用”。

### 5.2 标准化数据模型

系统内部统一使用标准记录结构来做分析，避免页面组件直接依赖原始上传文件格式。

这样带来的好处是：

- 页面逻辑和原始文件结构解耦
- 新数据源只要能进标准化层，后面图表都能复用
- 后续也更容易扩展成别的城市、别的数据主题

### 5.3 区域综合评分

为了解决“指标很多但难快速比较”的问题，系统会综合以下维度：

- 下载速率
- 时延
- 投诉率
- 满意度

经过归一化加权后，生成区域得分，用于做十八区横向比较。

### 5.4 自动洞察输出

除了图表，这个项目还会基于规则生成总结性结论，例如：

- 哪个区整体表现最好
- 哪个区最需要优化
- 哪个时段投诉压力最大
- 室内覆盖问题在哪些场景更明显

这样可以降低用户自己读图和整理汇报结论的成本。

## 7. 数据更新逻辑

用户上传新数据后，系统会执行以下流程：

1. 解析 `CSV / XLSX`
2. 识别表头并自动映射
3. 用户补充手动映射（如有需要）
4. 标准化所有记录
5. 重新计算总览指标、图表、区域评分和洞察
6. 页面自动刷新为新的分析结果

因此：

- 如果你上传 `3000` 条新数据，总览中的样本量会自动更新
- 如果你切换了筛选器，总览中的样本量会显示“当前筛选后的记录数”

## 10. 适合面试怎么讲

这个项目最适合从两个角度讲：

### 业务角度

- 这是一个把网络质量数据分析流程产品化的项目
- 它解决的是原始调查数据难复用、难对比、难展示的问题
- 重点不只是图表，而是让不同格式的新数据也能继续分析

- 这是一个基于 `React + TypeScript` 的可复用数据分析看板
- 核心在于“文件解析 + 字段映射 + 标准化模型 + 分析引擎 + 可视化”的完整链路
- 真正体现技术价值的点是可复用的数据标准化层，而不仅仅是页面展示
